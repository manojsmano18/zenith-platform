4. KEY ARCHITECTURAL & TECHNICAL TALKING POINTS FOR QUESTIONS
================================================================================

Q1: "How is data preserved if an EC2 instance reboots or container stops?"
A: "We use a Docker named volume (zenith_pgdata) mounted to /var/lib/postgresql/data.
   Even if the containers are destroyed and recreated, all customer accounts,
   products, and orders persist intact."

Q2: "How does the Frontend communicate with the Backend in Cloud?"
A: "We use NGINX as an API Gateway / Reverse Proxy on port 80. Browser calls
   /api/* which NGINX forwards internally to http://backend:8080/api/*. This
   prevents CORS issues and hides internal ports from public exposure."

Q3: "How is stock concurrency handled during high order volume?"
A: "Order placement runs within a Spring @Transactional boundary. It checks
   product.getStockQuantity() >= item.getQuantity() before deducting stock and
   saving, preventing negative inventory or race conditions."

Q4: "What security measures are implemented (DevSecOps)?"
A: - Shift-Left Security: Trivy vulnerability scanner runs in CI/CD before deploy.
   - Least Privilege: Backend Dockerfile switches to non-root 'spring:spring' user.
   - Path Traversal Defense: File uploads are sanitized against directory traversal.
   - Prepared Statements / ORM: Spring Data JPA prevents SQL Injection.
